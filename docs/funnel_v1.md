## 0. 왜 자체 구축인가

유료 대행(브랜딩+메타 광고+퍼널+CRM)이 파는 것은 「광고 → 폼 → 알림 → 상태 관리」다. 이 사이트는 이미 그 부품을 갖고 있다(§5). 대행이 갖지 못한 것은 둘이다.

1. **미끼의 실체** — 신순주가 실사용 중인 분석 프로그램(전 계약을 담보 단위로 쪼개 합산 → 담보별 판단 → 잔여 공백 경고). 「내 보험 무료 진단」이 아니라 **「보장분석 리포트」**로 건다(「무료」는 §6.10 금지어).
2. **컴플라이언스 운영 체계** — PAMS 심의 이력·preflight·금지어 게이트. 대행 소재가 심의 없이 나가면 제재는 신순주 개인이 맞는다(§6.4 500만원 실사례).

```
          │  POST /api/funnel/lead → funnel_leads (service_role 전용)
          ▼
[알림]  Soonjoo_PB 텔레그램 — 연령대·관심 분야·유입·접수번호·어드민 링크만
        (이름·번호·남긴 말씀은 싣지 않는다 → 대화방 기록이 3개월 파기 정책 밖에 남지 않게)
          ▼
[상태]  /admin/funnel — 신청 → 연락됨 → 분석완료 → 상담 → 계약 / 불발(사유)
        단계 바뀔 때마다 funnel_lead_events 기록(식별정보 없음, 파기 후에도 통계 유지)
          ▼

[오프라인] 상담에서 동의 → 설계사 권한으로 보험사 프로그램 조회 → 로컬 분석 프로그램 → 리포트 → 계약
```

### 상태 정의 [확정 — 코드 `LEAD_STATUSES`]

| 상태 | 뜻 | 누가 바꾸나 |
|---|---|---|
| 신청 | 폼 접수 | 자동 |
| 연락됨 | 순주가 통화·카톡 연결 | 순주/로버트 |
| 분석완료 | 동의 후 조회·분석 끝 | 〃 |
| 상담 | 리포트 설명 자리에 실제로 앉음 → **유효 상담** (`is_qualified=true` 자동) | 〃 |
| 계약 | 계약 체결 | 〃 |
| 불발 | 어느 단계든 종결 + 사유(연락 불가·의사 없음·대상 아님 등) | 〃 |

## 3. 광고 시험 설계 — 집행은 로버트 결정

### 3-1. 판

| 항목 | 안 |
|---|---|
| 매체 | 메타(인스타 피드·릴스 이미지 배치). 목표 = **랜딩 전환**(인스턴트 리드폼 아님) |
| 예산 | 일 2~3만원 × 14일 = **28~42만원** |
| 소재 | 3종 × 이미지 1장(영상 제외). 각 1건 심의 |
| 타깃 | 전국 · 35~59세 · 관심사 최소(메타 학습에 맡김). 지역 타깃 금지(§2 전국구) |
| 측정 | utm_content = 소재 ID. GA `lead_created`(form=funnel_v1) + DB events |

소재 3종 각도 [가설 — 심의 전 초안]
- **A 합산** 「보험 10개, 암 진단비는 합쳐서 얼마일까요」 — 각성 포인트(§2)
- **B 공백** 「제안서가 못 메운 구멍까지 보여주는 보장분석」 — 잔여 공백 경고
- **C 방법** 「관계가 아니라 분석으로. 담보 단위로 펼쳐 다시 설계합니다」 — 브랜드 한 줄

### 3-2. 지표와 손익분기

```
CPL  (신청 1건 비용)       = 광고비 / 신청 수
CPQ  (유효 상담 1건 비용)  = 광고비 / 상담 도달 수      ← 주 지표
CPA  (계약 1건 비용)       = 광고비 / 계약 수
상담→계약률 p               = 계약 / 상담
손익분기 CPQ*              = p × M
   M = 계약 1건당 신순주 순수입(수수료 − 직접비). 회사 지급 체계 내부 수치 → 로버트·순주가 채운다.
판정: 실측 CPQ ≤ CPQ* 이면 증액 검토, 2배 초과면 소재·랜딩 수정 후 재시험.
```

예시(전부 **[가설]**, 판단 근거로 쓰지 말 것): 42만원 집행 → 신청 20 → 연락 12 → 상담 6 → 계약 2 이면 CPL 2.1만 · CPQ 7만 · p=33%. M 이 30만원이면 CPQ* = 10만 → 통과.
⚠️ 14일·42만원은 통계적으로 작다. **소재 간 우열 판정이 아니라 「상담이 실제로 앉는가」 확인용**이다.

### 3-3. 중단 기준
- 7일 차 신청 0건 → 소재·타깃 점검 후 중단 여부 결정
- 신청 대비 연락 불가 50% 초과 → 폼 품질 문제(허위 번호) → 번호 인증 도입 검토
- 심의 지적·민원 1건 → 즉시 중단

## 4. 증권 PDF 업로드 — ⚠️ 헌법 충돌, v1 미구현

**충돌:** CLAUDE.md §2 「주민번호·계약 실데이터는 웹이 절대 수집·저장하지 않는다」, §6.1 「주민번호·계약 실데이터를 웹 폼으로 수집하는 설계는 어떤 경우에도 금지」. 증권 PDF 는 계약 실데이터이고 대개 주민번호 일부·병력 관련 특약·수익자 정보를 담는다(민감정보 가능).
→ **v1 폼에는 업로드가 없다.** 헌법을 바꿀지는 로버트 결정.

### 4-1. 권고 경로(헌법 유지)
상담 연결 후 **카카오톡 채널 1:1 로 수령 → 로컬 PC 분석 → 원본 즉시 삭제**. 웹·DB·Supabase Storage 를 거치지 않는다. 현행 사업 구조(§2 5~6단계)와 동일.

### 4-2. 그래도 웹 업로드를 한다면 — 최소 요건 (헌법 개정 + 법률검토 선행)
| 층 | 요건 |
|---|---|
| 동의 | 별도 동의(수집 항목에 「보험증권 사본」, 민감정보 포함 시 **별도 민감정보 동의**), 고유식별정보 처리 근거 검토 |
| 저장 | Supabase Storage **private 버킷**, 공개 URL 금지, 업로드는 서버 서명 URL(1회·5분), 파일명 = 랜덤 UUID |
| 암호화 | 전송 TLS + 저장 시 앱단 암호화(AES-256-GCM, 키는 서버 env, DB 와 분리) |
| 접근 | 다운로드는 어드민 서명 URL(1분)만, 다운로드마다 `access_log`(누가·언제·어느 파일) |
| 보관 | **7일** 후 자동 삭제(분석에 필요한 기간만). 리드 3개월보다 짧게 |
| 검증 | PDF 만, 10MB 이하, 매직바이트 확인, 실행 불가 |
| 사고 대응 | 유출 시 72시간 내 신고 의무 검토, 침해사고 절차 문서화 |
→ 이 비용과 위험에 비해 얻는 것(상담 전 분석)이 작다. **권고는 4-1.**
