## 0. 무엇이 불편한가

- 조합 제안은 보험사 1~5곳의 신규 제안서를 붙인다(CLAUDE.md 「조합 제안」). 지금은 **[📥 신규 제안 PDF] 를 보험사 수만큼 누르고, 파일 창에서 하나씩 고른다.**
- `<input type="file" id="newInput">`(1811행)에 `multiple` 이 없고, 처리기(4608행)가 `files[0]` 하나만 읽는다.
- 한 건 처리가 끝나면 상태 줄(`setNewStatus`, 4521행)을 덮어써서, 앞 파일의 「확인필요·미분류」 안내가 사라진다.
- 보험사 자동 판별(`detectInsurerFromPdf`, 4508행 — 본문 발행사명 → 파일명 → 「신규」)은 **이미 있다.** 빠진 것은 「여러 개를 한 번에 넣는 입구」와 「결과를 한 번에 보여 주는 요약」뿐이다.

## 2. 설계

### 2-1. 입구 두 개(같은 처리로 모은다)
1. **파일 창에서 여러 개 고르기** — `newInput` 에 `multiple` 추가. 처리기는 `Array.from(e.target.files)` 전체를 넘긴다.
2. **끌어다 놓기** — ① 편집 탭 상단에 「신규 제안서 PDF 를 여기에 끌어다 놓으세요(여러 개 가능)」 칸 하나. `dragover`/`drop`(기본 동작 막기) → PDF 만 골라 같은 처리로.
   - 🔴 KB 보장분석 PDF 는 이 칸으로 받지 않는다. **자동 분기(이 PDF 는 KB 분석이니 KB 로)는 하지 않는다** — KB 는 신규 제안서 발행사이기도 해서(KB 신규 제안) 오분기 위험이 크다. 칸 이름에 「신규 제안서」를 박고, PDF 가 아닌 파일은 건너뛰고 요약에 적는다.

### 2-2. 처리 = 기존 한 건 처리를 차례로
- `parseNewPdf` 를 **핵심(`parseNewPdfCore(file) → 결과`)과 겉(상태 줄·렌더)** 으로 나눈다.
  - 핵심 = 지금 4526~4540행 그대로(추출·판별·매핑·보험료 계산·`state.proposals.push`). **파서·매핑 호출 순서와 인자는 글자 그대로.**
  - 겉(한 건) = 지금과 같은 `setNewStatus` 문구 — **단건 업로드의 화면·문구는 바뀌지 않는다**(회귀로 고정).
- `parseNewPdfs(files)`(여러 건):
  1. PDF 만 남기고 **파일 이름순 정렬**(자연 정렬 — 「1. 삼성」「2. 미래에셋」… 습관 그대로 컬럼 순서가 된다).
  2. 같은 이름·같은 크기 파일이 한 번에 두 번 들어오면 한 번만(끌어다 놓기 중복 방지).
  3. `wasEmpty` 는 **묶음 시작 전에 한 번** 잰다 → 첫 건 뒤에 `detachStaleActiveIfNew(wasEmpty)` 한 번(새 고객 판정은 묶음 단위).
  4. 한 건씩 **차례로**(`await`) — pdf.js 동시 실행으로 메모리·순서가 흔들리지 않게. 한 건이 실패해도 다음 건 계속.
  5. 묶음 끝에 `saveState(); renderAll();` **한 번**(건마다 전체 재렌더하지 않는다).
  6. 진행 표시: 「신규 제안 PDF 분석 중… 2/4 (미래에셋)」.

### 2-3. 결과 요약(상태 줄 하나를 여러 줄로)
```
✓ 신규 4건 중 3건 적재
  · 삼성 — 담보 18 · 보험료 52,310원 · 확인필요 1
  · 미래에셋 — 담보 11 · 보험료 38,900원
  · 한화 — 담보 9 · 보험료 21,480원 · 미분류 2
  ⚠ 흥국(3. 흥국_제안.pdf) — 신규 제안 표를 찾지 못했습니다. 수동 입력 가능.
```
- 한 건이라도 확인필요·미분류·실패·표 인식 불완전이 있으면 경고 색(기존 `warn` 규칙 그대로).
- 이미 같은 보험사·같은 상품명 컬럼이 있으면 **막지 않고** 요약에 「⚠ 같은 상품이 이미 있음 — 중복이면 컬럼 삭제」 한 줄(기존 단건도 막지 않았다 — 동작 불변).

### 2-4. 순수 함수(vm 시험 대상)
- `pickPdfFiles(list) → {pdfs[], skipped[]}` — 확장자/`type` 로 PDF 만, 이름+크기 중복 제거, **자연 정렬**.
- `summarizeNewBatch(results) → {text, warn}` — 위 요약 문구.
- `parseNewPdfCore` 는 pdf.js 를 부르므로 vm 에서는 가짜 핵심으로 묶음 흐름만 본다(순서·실패 계속·렌더 1회·wasEmpty 1회).

## 4. 작업 순서 · 추정
1. 순수 함수 2개 + vm 시험(반나절)
2. `parseNewPdf` 핵심/겉 분리(글자 불변 확인) + `parseNewPdfs` 묶음 + `multiple` (반나절)
3. 끌어다 놓기 칸 + 진행 표시 + 요약(2~3시간)
4. 회귀 + 합성 PDF E2E + HANDOFF 확정결정 추가: 「신규 PDF 여러 개 = 이름순·차례 처리·실패 건 건너뜀·렌더 1회 · 자동 분기(KB↔신규) 없음 · 파서 불변」(반나절)
- 합계 약 1.5일. 원본 사본 + diff + 헤드리스 E2E 방식(1·2순위와 같게).

## 5. 하지 않는 것
- KB 보장분석 PDF·프라임 PDF 와의 자동 분기 — 오분기 위험(KB 는 신규 제안서 발행사이기도 하다).
- 병렬 처리 — 순서가 곧 컬럼 순서이고, pdf.js 동시 실행은 이득보다 위험이 크다.
- 파서·표 선택·추출 경계·매핑 변경 — 확정결정 10·11 그대로.
- 제안 컬럼 수 상한 신설 — 지금도 없고, 설계사가 1~5곳을 자유 구성한다.
